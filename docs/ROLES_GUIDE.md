# Руководство по ролям и доступам

## Обзор системы ролей

Приложение поддерживает три роли пользователей:

### 1. **Покупатель (Buyer)**
- **Доступ**: Просмотр товаров, создание заказов
- **Ограничения**: Не может добавлять товары, видить админ-панель
- **На фронтенде**: Видит кнопку "Новый заказ", не видит "Добавить товар"

### 2. **Продавец (Seller)**
- **Доступ**: Просмотр товаров, добавление новых товаров
- **Ограничения**: Не может создавать заказы, видеть админ-панель
- **На фронтенде**: Видит кнопку "Добавить товар", не видит "Новый заказ"
- **Меню**: Пункт "Управление товарами" в дропдауне пользователя

### 3. **Администратор (Admin)**
- **Доступ**: Полный доступ ко всем функциям (просмотр/добавление товаров, создание заказов)
- **На фронтенде**: Видит все кнопки и элементы управления
- **Меню**: Пункты "Управление товарами" и "Админ панель" в дропдауне пользователя

## Как работает система проверки доступов

### На Бэкенде (Flask)

1. **При регистрации** — пользователь выбирает роль (по умолчанию "buyer")
   ```python
   user = User(username=username, role=role)
   user.set_password(password)
   db.session.add(user)
   db.session.commit()
   ```

2. **При входе** — роль сохраняется в сессию
   ```python
   session['user_id'] = user.id
   session['user_role'] = user.role
   ```

3. **Проверка прав на маршруте** — бэкенд проверяет роль перед выполнением действия
   ```python
   if 'user_id' not in session:
       flash('Требуется авторизация', 'warning')
       return redirect(url_for('login'))
   current = User.query.get(session.get('user_id'))
   if not current or current.role not in ['seller', 'admin']:
       abort(403)  # Доступ запрещён
   ```

4. **Декоратор для защиты маршрутов** (опционально)
   ```python
   @role_required(['seller', 'admin'])
   def admin_only_route():
       pass
   ```

### На Фронтенде (JavaScript/HTML)

1. **Роль передаётся через атрибут body**
   ```html
   <body data-role="seller">
   ```

2. **JavaScript скрывает элементы, недоступные для текущей роли**
   ```javascript
   // В script.js
   const role = document.body.getAttribute('data-role');
   document.querySelectorAll('[data-role-allow]').forEach(el => {
       const allow = el.getAttribute('data-role-allow').split(',').map(s => s.trim());
       if (!allow.includes(role)) {
           el.style.display = 'none';
       }
   });
   ```

3. **HTML элементы отмечаются атрибутом data-role-allow**
   ```html
   <!-- Видно только для seller и admin -->
   <button data-role-allow="seller,admin">➕ Добавить товар</button>
   
   <!-- Видно только для buyer и admin -->
   <button data-role-allow="buyer,admin">➕ Новый заказ</button>
   ```

## Примеры использования

### Пример 1: Регистрация и вход

1. Откройте страницу `/register`
2. Введите:
   - Имя пользователя: `ivan_buyer`
   - Пароль: `password123`
   - Роль: **Покупатель**
3. Нажмите "Зарегистрироваться"
4. Откройте `/login`
5. Введите учетные данные и войдите
6. В навигации будет отображено: `ivan_buyer (buyer)`

### Пример 2: Разные права доступа

**Покупатель:**
- Может создавать заказы
- Не видит кнопку "Добавить товар"
- При попытке добавить товар через POST получает 403

**Продавец:**
- Видит кнопку "Добавить товар"
- Может добавлять новые товары
- При попытке создать заказ получает 403

**Админ:**
- Видит все кнопки и элементы
- Может выполнять все действия

### Пример 3: API endpoints

```bash
# Получить все товары (доступно всем, включая неавторизованных)
GET /api/products

# Получить все заказы (доступно всем)
GET /api/orders
```

## Безопасность

⚠️ **Важно:**

1. **Бэкенд-проверка обязательна** — фронтенд-скрытие элементов это только для UX, не для безопасности!
2. **Никогда не доверяйте клиенту** — любой пользователь может отредактировать HTML/JS и отправить запрос
3. **Всегда проверяйте роль на сервере** перед выполнением критичных операций

## Расширение системы

### Как добавить новую роль?

1. Обновите регистрацию (`register.html`):
   ```html
   <select class="form-select" id="role" name="role">
       <option value="buyer">Покупатель</option>
       <option value="seller">Продавец</option>
       <option value="moderator">Модератор</option>  <!-- Новая роль -->
       <option value="admin">Админ</option>
   </select>
   ```

2. Обновите проверки в `app.py`:
   ```python
   if current.role not in ['seller', 'moderator', 'admin']:
       abort(403)
   ```

3. Обновите условия в шаблонах:
   ```html
   {% if current_role == 'moderator' or current_role == 'admin' %}
       <!-- элементы для модератора -->
   {% endif %}
   ```
